# Baseline Profile: code AOT-compiled at install time (Play, or ProfileInstaller for sideloaded
# APKs) so cold start and the first page load do not run in the interpreter/JIT.
# https://developer.android.com/topic/performance/baselineprofiles/overview
#
# Library profiles (Compose, Activity, Navigation 3, Room, DataStore, …) ship inside their AARs
# and are merged automatically; these rules cover the app's own startup and browsing path:
# Application + Hilt graph, the launcher Activity, startup gate, onboarding, theme, navigation,
# tab restore, preferences, and the ad-block engine that filters every request of a page load.
# Feature pages opened later (downloads, share, settings, …) are left to the JIT.
#
# Hand-written wildcard rules. For measured, per-method precision, generate this file with the
# Baseline Profile Gradle plugin and a Macrobenchmark startup journey on a device.
